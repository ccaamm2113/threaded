Check it yourself

Download the full record and verify it per section: each section matches its own published hash, and each hash carries that section's own signature. The stable key signs only the live section — it never covers the archived rows. Any row can also be checked against Kalshi's own settlement record for that market.

1. Download every call

curl -sS -o record.jsonl {{ request.host_url }}api/record/export.jsonl
curl -sS -o export.json {{ request.host_url }}api/record/export.json

2. Split the download — the first archived_count lines are the archived section, the rest are the live section:

N=$(jq -r .archived_count export.json)
head -n "$N" record.jsonl > archived.jsonl
tail -n +"$((N + 1))" record.jsonl > live.jsonl

3. Nothing was edited — each section's hash must equal its published digest:

sha256sum archived.jsonl   # compare with: jq -r .archived.digestSha256 export.json
sha256sum live.jsonl       # compare with: jq -r .digestSha256 export.json
{% if envelope.signature %}

4. It really came from Threaded — verify each Ed25519 signature over its hex digest (as text, no trailing newline). Live section, stable key:

curl -sS {{ request.host_url }}api/record/public-key > pub.b64
{ echo "-----BEGIN PUBLIC KEY-----"; fold -w 64 pub.b64; echo; echo "-----END PUBLIC KEY-----"; } > pub.pem
printf '%s' "$(openssl dgst -sha256 -r live.jsonl | cut -d' ' -f1)" > digest.txt
jq -r .signature export.json | base64 -d > sig.bin
openssl pkeyutl -verify -pubin -inkey pub.pem -rawin -in digest.txt -sigfile sig.bin
# expected: Signature Verified Successfully

Archived section, original (pre-rotation) key — the key comes from export.json, not the live endpoint:

jq -r .archived.public_key export.json > oldpub.b64
{ echo "-----BEGIN PUBLIC KEY-----"; fold -w 64 oldpub.b64; echo; echo "-----END PUBLIC KEY-----"; } > oldpub.pem
printf '%s' "$(openssl dgst -sha256 -r archived.jsonl | cut -d' ' -f1)" > olddigest.txt
jq -r .archived.signature export.json | base64 -d > oldsig.bin
openssl pkeyutl -verify -pubin -inkey oldpub.pem -rawin -in olddigest.txt -sigfile oldsig.bin
# expected: Signature Verified Successfully

What counts

  • One call per window, latched. A call fires only after the entry gates pass on 2 consecutive polls. Once sealed it stays until a sell trigger fires or the window rolls — it never flip-flops.
  • Strong means the called side's ask was 75¢ or more at the seal.
  • Graded at settlement. Kalshi's own result decides win/loss; if Kalshi's API is unreachable at grading time, the last 1-minute candle close vs the target is used instead (marked grade_source: candle in the export).
  • Every sealed call counts. There is no "practice" bucket and no deletions. A call that fires is graded, win or lose.
  • The archive is preserved, not rewritten. Pre-rotation calls were imported verbatim into the archived section — same rows, same original signature, same originally published net edge. They are never re-signed, backdated, or re-priced under new fee math.
  • Research only. This record measures Threaded's calls. It is not financial advice, and past results say nothing about the next window.
