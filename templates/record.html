Check it yourself

Download the full record and verify it: the first archived.count lines verify against the original key, the rest against the current key. Any row can also be checked against Kalshi's own settlement record for that market.

1. Download every call

curl -sS -o record.jsonl {{ request.host_url }}api/record/export.jsonl
curl -sS -o export.json {{ request.host_url }}api/record/export.json

2. Split the download — the first archived.count lines are the original-key calls, the rest are the current-key calls:

N=$(jq -r .archived.count export.json)
head -n "$N" record.jsonl > original.jsonl
tail -n +"$((N + 1))" record.jsonl > current.jsonl

3. Nothing was edited — each part's hash must equal its published digest:

sha256sum original.jsonl   # compare with: jq -r .archived.digestSha256 export.json
sha256sum current.jsonl    # compare with: jq -r .live.digestSha256 export.json
{% if envelope.live.signature %}

4. It really came from Threaded — verify each Ed25519 signature over its hex digest (as text, no trailing newline). Current-key calls:

jq -r .live.public_key export.json > pub.b64
{ echo "-----BEGIN PUBLIC KEY-----"; fold -w 64 pub.b64; echo; echo "-----END PUBLIC KEY-----"; } > pub.pem
printf '%s' "$(openssl dgst -sha256 -r current.jsonl | cut -d' ' -f1)" > digest.txt
jq -r .live.signature export.json | base64 -d > sig.bin
openssl pkeyutl -verify -pubin -inkey pub.pem -rawin -in digest.txt -sigfile sig.bin
# expected: Signature Verified Successfully

Original-key calls — the key comes from export.json:

jq -r .archived.public_key export.json > oldpub.b64
{ echo "-----BEGIN PUBLIC KEY-----"; fold -w 64 oldpub.b64; echo; echo "-----END PUBLIC KEY-----"; } > oldpub.pem
printf '%s' "$(openssl dgst -sha256 -r original.jsonl | cut -d' ' -f1)" > olddigest.txt
jq -r .archived.signature export.json | base64 -d > oldsig.bin
openssl pkeyutl -verify -pubin -inkey oldpub.pem -rawin -in olddigest.txt -sigfile oldsig.bin
# expected: Signature Verified Successfully

What counts

  • One call per window, latched. A call fires only after the entry gates pass on 2 consecutive polls. Once sealed it stays until a sell trigger fires or the window rolls — it never flip-flops.
  • Strong means the called side's ask was 75¢ or more at the seal.
  • Graded at settlement. Kalshi's own result decides win/loss; if Kalshi's API is unreachable at grading time, the last 1-minute candle close vs the target is used instead (marked grade_source: candle in the export).
  • Every sealed call counts. There is no "practice" bucket and no deletions. A call that fires is graded, win or lose.
  • The first {{ summary.archived.total }} calls were imported verbatim. They came from the pre-rotation record — same rows, same original signature, same originally published net edge. They are never re-signed, backdated, or re-priced under new fee math.
  • Research only. This record measures Threaded's calls. It is not financial advice, and past results say nothing about the next window.
